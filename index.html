第一節：iPhone Duo 設計基礎（00:07:55）

分屏與畫中畫

  • 00:07:55新的並排分屏：沿用返回主畫面的手勢，把 App 拖到螢幕一側，就能把螢幕對半分成兩個獨立區域。
  • 00:08:24分屏時控制項會排到螢幕外側邊緣；App 在左側時按鈕也移到左側，方便左手拇指操作，也不會擋到中央。
  • 00:08:43畫中畫可以固定在螢幕頂部，下方 App 會在垂直方向自動調整尺寸；部分折疊時影片會填滿上半屏，下方 App 跟著即時調整。

讓設計適配 iPhone Duo

  • 00:09:18不必為每種姿態做專屬佈局，只要針對兩個尺寸類別設計：
    • 緊湊寬度（Compact）：例如外屏
    • 常規寬度（Regular）：例如展開後的內屏
  • 00:09:48不要用固定寬度、斷點，或綁定特定螢幕規格的度量單位。
  • 00:10:02使用佈局邊距（Layout Margin）和水平安全區內邊距；已經這樣做的 App，整體佈局大致已經能適配。
  • 00:10:16從一開始就把 App 設計成可以自由調整尺寸。
  • 00:10:39可選做法：平放桌面時提供免提體驗，媒體內容在上、互動元素在下方的穩定區域。但功能不能綁定特定姿態或佈局，階層和功能邏輯要和其他姿態一致。

控制項移到側邊

  • 00:11:09為了釋放縱向空間，多數介面的控制項會沿側邊排列。
  • 00:11:23例外：內屏直向時縱向空間足夠，控制項維持水平佈局。
  • 00:11:36側邊區域要和即時動態、狀態列等系統元素共用；空間不夠時，App 控制項會自動收進溢出選單（Overflow Menu）。
  • 00:12:03對應規則大多由系統自動完成：
    • 頂部工具列按鈕 → 垂直區域的頂端
    • 底部工具列按鈕 → 垂直區域的底端
    • Tab 欄（一級導覽）→ 維持在垂直區域底部
  • 00:12:36例外：寬度超過側邊空間的元素（文字按鈕、分段控制項）留在原本的頂部位置。

外屏內容佈局的三種做法（00:12:52）

  1. 00:13:10偏移內容：大多數內容要偏移，避開右側控制項；用了水平安全區內邊距就會自動偏移。
  2. 00:13:34全螢幕置中：不能捲動、沉浸式、高度視覺化的畫面可以全螢幕置中，只要互動元素不被右側控制項擋住。
  3. 00:13:55混合：背景圖或主標題全寬，可捲動的前景內容做水平偏移，互動元素放在可捲動區域內。

內屏最佳實踐（00:14:14）

  • 00:14:22分割檢視（Split View）可以同時呈現多個階層，但內外屏的資訊階層要一致，功能不能綁定特定螢幕狀態。
  • 00:14:46使用者會頻繁開合裝置，內外屏的行為要可預期、一致。
  • 00:14:57針對寬內屏優化，例如 Music 從縱向堆疊自動改成雙欄。
  • 00:15:16Tab 欄 App 可以在內屏改用側邊欄（Sidebar），適合資訊密集的產品，例如「健康」App。

模態面板（Sheet）與折疊處避讓

  • 00:15:44外屏：面板按鈕預設移到右側；可以停用面板的垂直欄，單一按鈕的面板效果最好，面板會停在前鏡頭下方。
  • 00:16:24內屏：直向或橫向都用標準的水平按鈕佈局。
  • 00:16:34部分折疊時，面板會自動滑向一側，避開折疊處。
  • 00:16:52彈出面板、提示、選單、工具列按鈕等系統元件都內建「避開折疊處」的行為，建議盡量用原生元件；內容本身通常不需要避讓折疊處。

小結

  • 00:17:26App 要提供一致的體驗，並適應不同螢幕尺寸和姿態；把控制項移到側邊、支援彈性調整尺寸。

第二節：技術準備（00:18:01，羅爽）

Xcode 與 SDK 版本的差異

  • 00:18:57用 iOS 26 SDK 建置：可以執行。合起時使用狀態列和鏡頭左側的空間；內屏以熟悉的尺寸和比例顯示，左右留黑邊。
  • 00:19:20用 iOS 27.0 SDK 建置：內屏顯示區延伸到狀態列左側，過去做的 iPhone 尺寸自適應都能發揮作用。
  • 00:19:42用 iOS 27.1 SDK 建置：顯示區延伸到螢幕邊緣，標準導覽和工具列按鈕會在狀態列下方垂直排列。
  • 00:20:07要完整的全螢幕體驗：下載 Xcode 27.1，選 iPhone Duo 模擬器，在 Device Hub 執行；底部控制可以展開、合上、旋轉、折疊。

通用自適應佈局

  • 00:20:25延續彈性佈局原則；00:21:17iOS 27 也能透過 Mac 上的 iPhone 鏡像調整 App 尺寸，原理和開合 Duo 相同。App 跨越尺寸類別時會調整佈局，但仍然是 iPhone App。
  • 00:21:40不要用 User Interface Idiom 判斷螢幕，要用尺寸類別：SwiftUI 用 Environment，UIKit 用 TraitCollection。
  • 00:22:09尺寸類別組合：
螢幕／方向寬高
外屏直向CompactRegular
外屏橫向CompactCompact（要特別注意）
內屏RegularRegular
  • 00:22:49外屏遵循 App 宣告的方向，可以趁機加入橫向支援（帳篷姿態）；內屏不遵循宣告的方向 → 不要用介面方向決定佈局，要用尺寸類別。
  • 00:23:22避免使用 MainScreen：有兩塊螢幕會產生歧義，未來也會淘汰。改用 Environment、Trait Collection、螢幕邊界；真的需要時用 window.screen。
  • 00:23:53同心圓角 API（iOS 26 推出，已支援 Duo 螢幕形狀）：SwiftUI ConcentricRectangle、UIKit UICornerConfiguration。
  • 00:24:18UIRequiresFullScreen 仍然有效，但開合時 App 還是會調整大小，並在內屏（含分屏）等比縮放。

iPhone Duo 專屬佈局

  • 00:24:57採用系統標準導覽：
    • SwiftUI NavigationSplitView／UIKit UISplitViewController：合上時多欄收成單一導覽堆疊，展開時並排或讓側邊欄覆蓋在詳情頁上
    • 00:25:25SwiftUI TabView／UIKit UITabBarController：預設內外屏都顯示 Tab 欄，必要時改垂直佈局
    • 00:25:45內屏可以改用側邊欄：SwiftUI 把 Default Tab Bar Placement 設為 Sidebar；UIKit 把 preferredPlacement 設為 Sidebar
  • 00:26:08Sheet：外屏按鈕可以垂直排列，內屏置中；Popover、Context Menu、Alert 會自動適應。

安全區與佈局邊距（00:26:33）

  • 導覽列、工具列、Tab 欄在安全區之外，會自動避開狀態列和鏡頭。
  • 互動的前景元素放在安全區內：SwiftUI 預設就在安全區內；UIKit 參考 safeAreaInsets 或用 Auto Layout 約束到 Safe Area Layout Guide。
  • 00:27:18背景可以鋪滿、延伸到欄的後方：SwiftUI 用 ignoresSafeArea，UIKit 用 bounds。
  • 00:27:30安全區不對稱（橫向、分屏時垂直按鈕可能在左側），要分別處理每一側；00:27:55Layout Margin 也不對稱。
  • 00:28:27測試方法：在 Device Hub 內屏拖動底部指示條，把 App 拖到兩側，驗證工具列在另一側的表現。
  • 00:28:49新 API（iOS 27.1）Reserved Region：SwiftUI ReservedRegion、UIKit UIView ReservedRegion，自訂欄位或延伸到邊界的 UI 用它避免和系統 UI 重疊。
  • 00:29:17安全區最佳實踐：① 優先用系統標準欄 ② 互動前景元素約束在安全區內，背景可以延伸 ③ 考慮並測試安全區和邊距的不對稱 ④ 複雜佈局用 Reserved Region。

App Resizability Skill

  • 00:30:05原本用於 App 現代化的 Skill，在 Xcode 27.1 改名為 App Resizability，除了 UIKit 也支援 SwiftUI，並針對 iPhone Duo 優化。

小結

  • 00:30:31用 Xcode 27.1 編譯 → 用 Device Hub 在 Duo 模擬器測試各種姿態 → 遵循自適應佈局最佳實踐，並試用 App Resizability Skill。

第三節：控制欄設計（00:31:02，Izzy）

基本原理

  • 00:31:27Duo 的寬高比較大，頂部和底部的互動元素移到側邊，讓外屏有更多垂直空間；內屏橫向時位置一致。
  • 00:32:17內屏直向時恢復成頂部和底部的水平控制欄；這些都是同一套元件，只是適應不同環境。
  • 00:32:51本節四個主題：適應新軸向、元素排列與容器互動、垂直內容調整、溢出選單。

基礎適配（00:33:24）

  • 00:33:50用最新 SDK 重新編譯，原生控制項就會自動完成基本調整。
  • 00:34:02使用標準導覽容器：
    • SwiftUI：toolbar 修飾符搭配 NavigationStack／NavigationSplitView
    • UIKit：UINavigationController、UITabBarController，把工具列項目設在 ViewController 上，不要自建 UIToolbar
  • 00:34:42用 UIToolbar／UINavigationBar／UITabBar 自建的欄，不會被移到側邊。

元素排列與容器（00:35:00）

  • 00:35:10導覽列、工具列、Tab 欄可以共存在同一區域，可以想成旋轉 90° 形成垂直堆疊。例如備忘錄只有工具列，時鐘只有 Tab 欄，健身兩者都有。
  • 00:35:54只有容器本身在螢幕邊緣時，工具列才會變縱向。例如分割檢視中只有右側詳情欄會變，側邊欄和檢查器面板維持水平。
  • 00:36:36外屏的模態面板工具列預設垂直；內屏預設置中、水平。用 preferredPlacement 把面板放到右側時，工具列會變垂直，放左側則不變。
  • 00:37:08垂直欄和硬體對齊，在由右至左（RTL）語系中也固定在同一側；內容會鏡像，欄不會。
  • 00:37:44垂直顯示時維持由上而下的階層：
    • 最上方：返回／關閉。系統導覽會自動加返回；自訂的用 SwiftUI cancellationAction、UIKit leadingItem，並把 leftItemsSupplementBackButton 設為 false
    • 接著：最關鍵的操作（完成、儲存）。SwiftUI 用 topBarPinnedTrailing，UIKit 用 Pinned Trailing Group
    • 其他元素保留原本分組，頂部和底部群組之間用間距分隔
  • 00:39:03不是所有姿態都會垂直排列，要保持空間關係一致，讓使用者不必重新學習位置。

垂直欄的內容（00:39:22）

  • 00:39:38水平欄：高度固定、寬度彈性；垂直欄：寬度固定、高度彈性 → 垂直欄適合圖示。
  • 00:40:01每個元素都要提供圖示＋標題，由系統決定呈現方式：欄中優先顯示圖示；沒有圖示就顯示文字；在溢出選單中兩者都顯示。
  • 00:40:53有圖示的按鈕會移到縱軸，純文字按鈕留在水平軸。用 SwiftUI Label 或 UIBarButtonItem 屬性設定就已經準備好了。
  • 00:41:41即使只是圖形也要給標題（溢出選單、展開狀態會用到）。
  • 00:42:12新的 Axis Behavior API：
    • 會在文字和圖示間切換的自訂按鈕（例如編輯↔完成）→ Horizontal Only（系統編輯按鈕已自動處理）
    • UIKit 自訂視圖、SwiftUI 複雜視圖預設維持水平；適合垂直的（例如右上角指南針）→ Vertical Preferred
  • 00:43:39減少純文字或文字＋圖示的自訂按鈕。例如數字改用徽章（iOS 26 Badge API）；00:44:26文字只是補充就只用圖示，必要文字（例如購物車總額）可以做成橫向大按鈕。
  • 00:45:09附屬視圖（Accessory View）永遠跟著鍵盤，不移到縱軸。
  • 00:45:18自訂底欄要移到縱軸：元素要符合縱欄固定寬度，或有垂直自適應佈局，例如垂直時隱藏標題、略微縮短高度。
  • 00:45:52讀取 SwiftUI verticalBarEdge 環境值或 UIKit 對應的 trait；不在垂直欄時回傳 nil／未指定。
  • 00:46:14垂直欄預設沒有捲動邊緣效果；開啟「降低透明度」時有背景，自訂視圖也要對應調整樣式。
  • 00:46:32彈性間距在縱軸高度為 0，固定間距保留最小尺寸；元素之間不需要額外間距。

溢出選單（00:46:58）

  • 00:47:05縱向空間有限，還可能和鍵盤、畫中畫競爭空間。
  • 00:47:18決定哪一條欄要更長時間可見：
    • 以內容瀏覽為主（例如 Podcast）：預設先壓縮工具列，Tab 欄保持可見
    • 以任務為主（例如遊戲 App）：先壓縮 Tab 欄
    • 用 Toolbar Vertical Compression Behavior API 設定
  • 00:48:18已有的溢出選單要整合到系統管理的選單：SwiftUI ToolbarOverflowMenu，UIKit additionalOverflowItems。
  • 00:48:36省略號圖示是 iOS 標準的溢出選單圖示，不要挪作他用，也不要換成其他平台的圖示。
  • 00:49:09Visibility Priority API：預設由下而上收合，可以對群組或單一按鈕設高、低或自訂優先級。高頻操作（寫郵件、新增筆記）和帶未讀徽章的按鈕要保留最久。
  • 00:50:30不適合移到側邊的情況：
    • 單一畫面、下方內容很重的 App（例如計算機）：維持頂部水平工具列
    • 內容操作很多、只有一個關閉按鈕的模態面板：停用垂直工具列
    • 用 Toolbar Vertical Behavior／Preferred Vertical Bar Behavior 停用

小結

  • 00:51:26用最新 SDK 建置 → 檢查各控制欄 → 更新自訂控制項支援垂直 → 設定溢出優先級。

第四節：保留區域、位移與排列模式（00:52:17）

保留區域（Reserved Region）

  • 00:52:32Duo 的硬體特性（鉸鏈、內外屏兩顆前鏡頭）在螢幕上對應的區域稱為保留區域。
  • 00:52:54外屏鏡頭一直存在，和狀態列、工具列、Tab 欄一起在側邊安全區縱向排列；內屏要針對中央折疊處和啟用中的前鏡頭調整。
  • 00:53:27兩種模式：位移模式（前面多數調整都屬於這類）和新的排列模式（Arrangement）。

位移模式（00:53:50）

  • 00:54:03依可用空間變化動態調整元素，讓內容在部分折疊時仍然可見、可用。中央的元素折疊後移到能發揮功能的區域。
  • 00:54:35位移的範圍可以是控制項、容器或整塊佈局：能獨立成立的元素單獨位移，有協同關係的一起位移。
  • 00:55:06避免位移太遠，否則會削弱和內容的視覺關聯。例如在相簿長按照片出現選單，折疊時選單要和照片一起移動。
  • 00:55:49可連續捲動的內容（文章、文件、列表、動態）不位移，以免打斷捲動。
  • 00:56:08位移方向依用途和姿態決定：
    • 部分折疊時，Alert 移到裝置末端一側，闔上後位置仍連貫
    • 00:56:35筆電（坐立）姿態：Alert 移到上半屏，媒體控制等互動元素移到下半屏
    • 00:57:00有多個目標區域時選最能保持脈絡的。例如備忘錄搜尋框吸附在鍵盤上方，折疊時移到被搜尋內容所在的那一半
  • 00:57:27位移後的調整：位置、尺寸，也可能包括圓角、邊距。
    • 00:57:51Action Sheet、Alert、選單、Popover 等輕量元件：系統自動重新定位到保留區域周圍
    • 00:58:17尺寸：提醒事項的分割檢視會自動調成 50/50；健身卡片會加大折疊處的間距

保留區域 API（00:59:17）

  • 00:59:29SwiftUI：從 GeometryReader 或 onGeometryChange 的 GeometryProxy 呼叫新的 reservedRegions；UIKit：UIView 的 reservedRegions，可以讀取 frame。
  • 類型：
    • Division（分隔）：中央折疊處，把大區域切成小區域
    • 01:01:04Occlusion（遮擋）：例如 FaceTime 鏡頭，相機啟用時才會啟用
  • 01:00:18預設只回傳啟用中的區域，用 includeInactive 可以查詢未啟用的。折疊處只有在開始折疊時才啟用，未折疊時寬度為 0。
  • 01:00:52可以預先規劃，例如讓網格在分隔區兩側的欄數相等。

排列模式 Arrangement（01:01:40，01:02:44 起由羅爽說明）

  • 01:01:45導覽容器（NavigationStack、NavigationSplitView、TabView）和內容容器（List、ScrollView）之間，新增一類佈局容器，依規則決定兩個視圖的關係。
  • 01:02:53範例：Podcast 的播放中畫面點「文字稿」會一分為二；關掉文字稿後，播放控制不會像 iPad 那樣置中，而是留在折疊處左側；直向時文字稿改為內嵌顯示。
  • 01:04:06輸入：水平／垂直尺寸類別、寬高比、是否有啟用中的分隔區域 → 輸出：是否顯示視圖、frame 多大。這個函式就是 Arrangement（iOS 27.1 提供）。
  • 01:04:57實作（語音備忘錄範例）：
    • SwiftUI：在 NavigationStack 中放 ArrangementView（primary：Player View，secondary：Up Next View）
    • UIKit：UIArrangementViewController 作為 UINavigationController 的 root，設定 primary／secondary
  • 01:05:57arrangementViewStyle：
    • Split（預設，拆分）：寬大於高時水平拆分，旋轉後垂直排列。01:06:43可以用 axis 限定 horizontal；無法在指定軸向排列時只顯示 primary。UIKit 用 updateArrangement
    • 01:07:26Overlay（疊加）：傾向上下疊加，折疊時改成並排。可以讀取環境值 overlayArrangementZIndex，在收合／展開樣式間切換；UIKit 用 state 的 zIndex
  • 01:09:05怎麼選：
    • 原本用 HStack／VStack → Split；用 ZStack → Overlay
    • 有明顯前景／背景關係（例如閱讀器，控制項在前）→ Overlay
    • 主視圖＋詳情、不互相遮擋（例如 Podcast 文字稿）→ Split
  • 01:10:29限制：不提供導覽架構，不要把 NavigationSplitView 等導覽容器放進 ArrangementView，也不要把 ArrangementView 放進 List、ScrollView 這類可捲動容器。

小結

  • 01:11:04檢查置中佈局，考慮改雙欄或選擇位移方式；標準容器已經做了多數適配；自訂的水平拆分或疊加改用 Arrangement View（所有 iOS／iPadOS 裝置都支援）；優先級最高的手動佈局控制項採用 Reserved Region API。

第五節：鉸鏈、多工處理、場景配件（01:32:21，Peter）

鉸鏈 API

  • 01:33:10桌布會依鉸鏈角度動態縮放，App 也可以回應鉸鏈變化。
  • 01:33:25SwiftUI onHingeChange 修飾符、UIKit UIHingeInteraction：
    • 離散狀態：關閉、部分展開、完全展開
    • 另外提供鉸鏈角度的連續更新
  • 01:33:53範例（空氣吉他）：用鉸鏈開合驅動像搖桿一樣的彎音效果。
    • 閉包接收前後兩個狀態
    • hinge 為 nil 代表裝置沒有鉸鏈
    • 只在半展開時接收更新，其他情況把彎音歸零
    • 用連續角度計算彎音幅度
  • 01:35:28鉸鏈資料適合驅動動態互動和視覺特效；處理版面時，請改用 Arrangement 和 Reserved Region API。

多工處理

  • 01:35:46Duo 上所有 App 都參與多工處理，兩個 App 可以並排分屏；已在 iPad 或 iPhone 鏡像支援視窗縮放的 App 已經有好的起點。
  • 01:36:10新佈局：影片播放器和 App 堆疊，處理方式和分屏相同，用 Size Class 和 Scene Geometry 做佈局決策。
  • 01:36:38Duo 是第一款支援 App 多視窗的 iPhone，iPad 的多視窗實作可以直接用。
    • 但 iOS 上只有 Duo 支援多視窗 → 要在執行時判斷可用性，請求新 Scene 時妥善處理例外
    • 建議用 UIWindowScene 的 Activation Action，不能開新視窗時會自動隱藏

場景配件（Scene Accessory）

  • 01:37:33讓 App 同時在多塊螢幕呈現內容，例如 iPhone 當外接螢幕遊戲的手把。系統會動態控制可用性，要觀察並回應變更。
  • 01:38:18新的 Camera Capture Accessory：主介面在內屏時，外屏顯示附加 UI（例如幫別人拍照時給對方看的內容）。
    • 條件：App 在內屏全螢幕執行，而且有啟用中的相機工作階段
    • 要在相機 UI 所在的視圖上註冊
  • 01:39:17範例（演講排練 App）：錄影時在外屏顯示提詞器。
    • 用 Scene Accessory 修飾符加到相機視圖上，相機視圖可見時就會顯示
    • 用工具列按鈕切換 isEnabled
    • 用 Availability Change 修飾符監聽可用性，例如裝置闔上時停用按鈕

第六節：相機體驗（01:41:33，Peter）

兩顆前鏡頭與虛擬前鏡頭

  • 01:42:10Duo 是第一款有兩顆前鏡頭的 iPhone，兩顆都是超廣角方形感光元件；內屏那顆是 iPhone 第一個螢幕下鏡頭。
  • 01:42:39用 AVFoundation 採集；AVCaptureDevice.DiscoverySession 請求 Front 位置，搭配廣角或超廣角類型，會發現新的虛擬前鏡頭。
  • 01:43:12虛擬前鏡頭會自動切換：展開時用內屏鏡頭，闔上時用外屏鏡頭。

直接使用實體鏡頭

  • 01:44:10裝置類型：builtInOuterUltraWide（外屏）、builtInInnerUltraWide（內屏）。
鏡頭最高規格
內屏超廣角1080p／60fps
外屏超廣角4K／120fps
虛擬前鏡頭兩顆統一為 1080p／60fps
  • 01:45:12深度資訊只在單獨使用實體鏡頭時支援；直接使用實體鏡頭時，開合切換要由 App 自己負責。

方向協調器 AVCaptureDevice.DirectionCoordinator（01:45:40）

  • 01:45:47內外屏的前鏡頭 position 都是 front，但兩面朝向相反，所以「front」不一定正對使用者；展開後翻面，也可以用後鏡頭自拍。
  • 01:47:17建立時需要：一個 UIView、要監聽的裝置類型、狀態變更回呼（初始化後立即呼叫一次，之後方向改變時觸發）。
  • 01:47:45回報情境：
    • 視圖在外屏：外屏前鏡頭朝前，後鏡頭朝後
    • 展開，視圖移到內屏：外屏前、後鏡頭都朝後，內屏前鏡頭朝前
    • 展開後翻面，App 移到外屏：後鏡頭和外屏前鏡頭都朝前
  • 01:48:40同時用兩塊螢幕時（兩個 UIView），每個視圖各建一個協調器，方向都是相對於該視圖所在螢幕；要透過 Scene Accessory API 開啟雙螢幕能力。
  • 01:49:42協調器隔離在 Main Actor：回呼中不要直接呼叫 AVFoundation。它提供 AVCaptureDeviceDescriptor（Main Actor 安全、Sendable），可以安全傳給 Camera Actor 再建立裝置。
  • 01:50:32開合時：依回呼重新設定 AVCaptureSession，切到正對使用者的鏡頭；後鏡頭變成朝前時要開啟預覽鏡像。API 在 AVKit。

相機預覽優化（01:51:30）

  • 01:51:41內屏用後鏡頭完整視野取景時周圍會有多餘空間：可以偏移預覽，把拍照控制項集中在剩餘區域，或讓預覽填滿螢幕。用 AVCaptureVideoPreviewLayer.videoGravity 控制。
  • 01:52:36超廣角前鏡頭可以利用方形感光元件填滿螢幕：用 AVCaptureDevice 的動態寬高比，在內屏選橫向比例（參考 WWDC26 方形感光元件影片）。
  • 01:53:04用 AVCaptureDevice.RotationCoordinator 確保預覽和照片永遠正向；跨螢幕切換時會自動更新。接入後要停用鏡頭感光元件方向補償以提升效能（Duo 所有前鏡頭預設開啟）。

行動建議

  • 01:54:03用 iOS 27.1 SDK 建置 → 用方向協調器處理開合時的鏡頭切換 → 在 Duo 上充分測試各形態的相機預覽。
